# ADR 005：三引擎工作室定位（部分修订 ADR 004）

- 状态：已接受
- 日期：2026-07-24
- 关联：[三引擎策略](../strategy/three-engine-studio.md)、ADR 004、ADR 003

## 背景

ADR 004 将业务定位为"AI 漫剧 IP 试制与验证平台"。进一步的行业分析表明：
建立在单一内容形态（漫剧）上的定位仍然脆弱——模型成本两年降逾 280 倍、
平台流量玩法快速更替，"会调用模型"不构成壁垒。个人开发者更稳的结构是
三台引擎：**垂直服务现金流 → 沉淀内部软件 → 同一套能力孵化自有 IP**。

## 决策

1. **定位修订**：从"漫剧 IP 试制平台"拓宽为"面向 AI 产品、App 和独立游戏的
   多模态内容发布与本地化工作室"。**ADR 004 中漫剧相关的生产决策全部保留**
   （三档交付、漏斗与止损、题材原则），但漫剧从"全部业务"降级为
   "首个垂直场景 + 自有 IP 孵化载体"。
2. **精力分配**：70% 有明确付款人的垂直服务 / 20% 内部自动化 / 10% 自有 IP。
3. **服务产品化**：套餐 A（产品发布基础包 ¥2,000–5,000）、套餐 B（游戏叙事
   宣传包 ¥5,000–15,000）、套餐 C（持续合作，固定费 + 用量）。不做无限定制、
   不做"无限生成"纯订阅。
4. **内部操作系统七模块**作为产品建设清单：项目知识库、任务模板、
   模型适配器（已有）、资产管理（已有）、人工审批（已有）、成本账本（已有）、
   导出系统。**先有付费客户，再补自助 SaaS**。
5. **自有 IP 首发形态**改为互动网页故事/视觉小说/短篇叙事游戏/角色化 AI
   体验，而非长篇动画；预算 ≤ 月可支配利润 10–20%。
6. **十条止损规则**采纳为经营纪律（见策略文档），其中工程相关三条：
   无付费客户不做完整 SaaS；单自动化模块 ≤ 2 周；不买 GPU。
7. **AI 辅助开发纪律**：人写需求与数据结构、人审测试、人负责合并排错；
   AI 不独自决定架构。

## 对工程路线图的影响

- 数据模型：`Project` 增加"交付物类型"概念（短剧/产品发布包/游戏叙事包/
  社交内容包等），一个项目可产出多种交付物（"一个输入，多种输出"）。
- 新增模块规划：**项目知识库**（品牌语气/禁忌/IP 设定，Phase 2）、
  **任务模板**（按套餐定义交付物清单与工作流，Phase 2）。
- 短剧管线建设顺序不变（剧本→镜头→合成→样片），但其产物只是交付物
  类型之一。
- 多语言管线（ADR 004 第 7 条）优先级提升：它是套餐 A/B 的标配能力，
  从 P3 提前到 P2 后期。

## 已评估但未采纳

- 泛化"AI 万能工具"或通用聊天/写作 App（同质化、留存差）。
- 内容农场/短视频矩阵（平台政策与变现风险）。
- 自研基础模型或 GPU 平台（不适合个人开发者）。

## 冲突解决

若 ADR 004 与本 ADR 冲突，以本 ADR 为准；ADR 004 未被点名的条款继续有效。
