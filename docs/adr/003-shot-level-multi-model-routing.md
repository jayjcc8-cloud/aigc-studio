# ADR 003：分镜级多模型路由与"配音/Animatic 优先"生产策略

- 状态：已接受
- 日期：2026-07-24
- 关联：[策略文档](../strategy/multi-model-routing.md)、ADR 002（Provider 抽象）

## 背景

单一"最强视频模型"生成整部短剧在实践中不可行：不同模型在角色一致性、
对白口型、复杂动作和成本上各有优劣；且短剧生产需要大量重试，真正的优化
目标是**每个可用镜头的成本**而非每秒标价。

## 决策

1. **镜头路由器**：每个 Shot 携带 `model_tier`（draft/performance/dialogue/
   complex/hero）、`max_attempts`、`budget_cny`。路由用确定性规则实现，
   不交给 LLM 自由决策。
2. **Animatic 先行**：视频生成前先产出静帧分镜 + 临时配音预演并过一审，
   砍掉不值得花视频预算的镜头。
3. **配音优先**：对白镜头先定稿 TTS 得到精确音频时长，分镜时长匹配音频，
   而非先画面后硬配音。
4. **成本按可用秒核算**：候选一律 720P，过审后再超分；口型问题走廉价修复
   服务而非重生成；单模型最多重试 1–2 次后按阶梯降级处理。
5. **合规入流水线**：导出环节强制"AIGC 显式标识 + 元数据 + 平台 AI 声明"
   （《人工智能生成合成内容标识办法》2025-09-01 施行）。
6. **基准集驱动选型**：以 30 个代表镜头的内部盲评结果决定各档位供应商，
   而非外部榜单。

## 供应商布局

- 主网关：阿里云百炼（Wan 系列、HappyHorse、Kling、PixVerse 均在百炼可调用）。
- 副供应商：MiniMax（Hailuo 视频 + Speech 配音）。
- Hero 镜头：Seedance 2.0 / Gemini Omni Flash（5–10% 流量）。
- 全部通过 ADR 002 的 Provider 抽象接入，替换供应商不改业务代码。

## 已评估但未采纳

- **n8n 编排（MVP 阶段）**：我们已有 Python 流水线骨架，再引入 n8n 会多出
  一套运行时与运维面。MVP 编排留在 Python；当运营团队需要可视化流转/
  表单驱动时再以 FastAPI 为媒体网关接入 n8n。
- **自建 GPU 集群**：当前 API 优先、ComfyUI 仅承担角色图/修图/超分等局部
  本地化任务；月产量稳定后再按"每可用秒成本"评估自建盈亏平衡。

## 后果

- `Shot` 模型新增路由字段（向后兼容，带默认值）。
- 新增里程碑工作项：镜头路由器、Animatic 生成、自动质检、合规导出、
  基准集与盲评流程。
- 成本统计维度从"每次调用"升级为"每镜头候选数 / 每可用秒成本"。
